// Return type: kern_return_t — MUST check == KERN_SUCCESS

Delta calculation formula (from RESEARCH.md):
```
userDiff = current.cpu_ticks[0] &- previous.cpu_ticks[0]
sysDiff  = current.cpu_ticks[1] &- previous.cpu_ticks[1]
idleDiff = current.cpu_ticks[2] &- previous.cpu_ticks[2]
niceDiff = current.cpu_ticks[3] &- previous.cpu_ticks[3]
totalTicks = userDiff + sysDiff + idleDiff + niceDiff
usage = ((userDiff + sysDiff + niceDiff) / totalTicks) * 100.0
```
Use `&-` (subtract with overflow) per RESEARCH.md A3 — Stats production pattern.

    - `private var previousCPUInfo = host_cpu_load_info()` — stored previous tick counters for delta calculation
    - `private var hasPreviousCPUInfo = false` — flag for first-read skip
    - `private var lastDisplayedCPU: Double?` — for tracking displayed value (enables tolerance check from D-06)

    **`applicationDidFinishLaunching(_:)`:**
    - Create NSStatusItem: `NSStatusBar.system.statusItem(withLength: NSStatusItem.variableLength)` (D-08)
    - Set `statusItem?.autosaveName = "com.macstatus.cpu"` — remembers position across app restarts

    - Call `startPolling()` immediately

    **`startPolling()`:**
    - Fire first read immediately on background queue: `DispatchQueue.global(qos: .utility).async { [weak self] in self?.readCPU() }` — LIFE-03 zero-config startup, data appears within ~10ms of launch
    - Schedule repeating timer: `Timer.scheduledTimer(withTimeInterval: 2.0, repeats: true)` (D-05)
    - Timer block: `[weak self] _ in DispatchQueue.global(qos: .utility).async { self?.readCPU() }` — all Mach calls on .utility queue, never on main thread (ARCHITECTURE.md Anti-Pattern 1)
    - Add timer to RunLoop: `RunLoop.main.add(timer, forMode: .common)` — ensures timer fires during menu tracking and other modal states

    **`readCPU()` — executes on background queue:**
    - Declare `var cpuLoadInfo = host_cpu_load_info()` (stack-allocated, no vm_deallocate needed per RESEARCH.md)
    - Declare `var count = mach_msg_type_number_t(MemoryLayout<host_cpu_load_info>.stride / MemoryLayout<integer_t>.stride)`
    - Call `host_statistics(mach_host_self(), HOST_CPU_LOAD_INFO, &cpuLoadInfo, &count)` via `withUnsafeMutablePointer` rebind pattern from RESEARCH.md code example
    - Guard `result == KERN_SUCCESS` — on failure, dispatch `nil` to main thread for "--" display (RESEARCH.md §Common Pitfalls #4)
    - If `!hasPreviousCPUInfo`: store current as previous, set flag true, return (skip first read — no delta possible)
    - Delta calculation using `&-` (subtract with overflow per RESEARCH.md A3):
      - `userDiff = Double(cpuLoadInfo.cpu_ticks.0 &- previousCPUInfo.cpu_ticks.0)`
      - `sysDiff = Double(cpuLoadInfo.cpu_ticks.1 &- previousCPUInfo.cpu_ticks.1)`
      - `idleDiff = Double(cpuLoadInfo.cpu_ticks.2 &- previousCPUInfo.cpu_ticks.2)`
      - `niceDiff = Double(cpuLoadInfo.cpu_ticks.3 &- previousCPUInfo.cpu_ticks.3)`
    - `totalTicks = userDiff + sysDiff + idleDiff + niceDiff`
    - Update `previousCPUInfo = cpuLoadInfo`
    - Guard `totalTicks > 0` — if 0, dispatch 0.0 to main thread
    - `usage = ((userDiff + sysDiff + niceDiff) / totalTicks) * 100.0`
    - Dispatch to main: `DispatchQueue.main.async { [weak self] in self?.updateDisplay(usage.isNaN ? nil : usage) }`

    **`updateDisplay(_ value: Double?)` — executes on main thread:**
    - If `value == nil`: set `attributedTitle` to `attributedString("CPU --%")`, reset `lastDisplayedCPU = nil`, return
    - D-06 tolerance check: `if let last = lastDisplayedCPU, abs(value - last) < 0.5 { return }` — skip redraw for insignificant changes
    - `lastDisplayedCPU = value`
    - `statusItem?.button?.attributedTitle = attributedString(String(format: "CPU %.0f%%", value))` — D-04 format

    **`attributedString(_ text:) -> NSAttributedString`:**
    - Font: `NSFont.monospacedDigitSystemFont(ofSize: NSFont.smallSystemFontSize, weight: .regular)` — D-07, prevents menu bar jitter from proportional digits
    - Color: `NSColor.labelColor` — auto-adapts to light/dark mode (PITFALLS.md §UX Pitfalls)
    - Return `NSAttributedString(string: text, attributes: [.font: font, .foregroundColor: color])`

    **`stopPolling()`:**
    - `timer?.invalidate()`
    - `timer = nil`

    **`applicationWillTerminate(_:)`:**
    - Call `stopPolling()`
    - Cleanup status item: `if let item = statusItem { NSStatusBar.system.removeStatusItem(item) }` — D-10, PITFALLS.md Pitfall 1 ghost icon prevention
    - `statusItem = nil`

    **`deinit`:**
    - PRINT statement for verification: `print("AppDelegate deinit — status item cleaned up")` — verifies no retain cycles (PITFALLS.md §Performance Traps — retain cycle Timer→self)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App process → Mach kernel | `host_statistics()` crosses user→kernel boundary. Kernel returns tick counters through a memory pointer. |
| Background queue → Main thread | `DispatchQueue.main.async` bridges CPU data from background queue to UI thread. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Denial of Service | `readCPU()` — `host_statistics()` call | mitigate | Check `kern_return_t` against `KERN_SUCCESS` on every call. On failure, call `updateDisplay(nil)` → display "CPU --%" (degraded mode). Do NOT crash or retry-loop. Documented in RESEARCH.md §Common Pitfalls #4. |
| T-01-02 | Denial of Service | `Timer.scheduledTimer` closure | mitigate | Use `[weak self]` in all Timer blocks. `applicationWillTerminate` calls `timer?.invalidate()`. `deinit` includes print statement for verification. Prevents retain-cycle memory leak. Documented in PITFALLS.md §Performance Traps. |
| T-01-03 | Spoofing | `NSStatusItem` lifecycle | mitigate | `applicationWillTerminate` calls `NSStatusBar.system.removeStatusItem(item)` explicitly. Prevents ghost icon accumulation that could mislead users about how many instances are running. Documented in PITFALLS.md Pitfall 1. |
| T-01-04 | Information Disclosure | `NSStatusBarButton.attributedTitle` | accept | Menu bar text is visible to all users of the machine. CPU usage percentage is non-sensitive system data. No privacy risk. |
</threat_model>
