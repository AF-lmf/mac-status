## Spacing Scale

Declared values for new or modified Phase 12 layout code. Values are in macOS points and must stay on multiples of 4 unless listed as a legacy exception.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Caption gaps, stacked fan captions, tiny row vertical rhythm |
| sm | 8pt | Row label/value gap, card grid gap, section vertical spacing |
| md | 16pt | Reserved for larger internal grouping only; do not use for normal popover rows |
| lg | 24pt | Not used in the compact popover |
| xl | 32pt | Not used in the compact popover |
| 2xl | 48pt | Not used in the compact popover |
| 3xl | 64pt | Not used in the compact popover |

Exceptions:

- Existing `DashboardView` outer padding may remain `12pt`; it is part of the current compact popover proportion.
- Existing card padding should use `8pt` when Phase 12 touches that surface; untouched legacy values are not declared as Phase 12 spacing exceptions.
- No touch-target exception is needed in this phase; the popover is pointer-driven and Phase 12 does not add controls.

## Typography

Use exactly these four type roles in Phase 12 touched popover surfaces. Do not introduce hero/display sizing, marketing type, or larger dashboard headings.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Micro metadata | 9pt | regular 400 | 1.15 |
| Label / caption2 | 11pt | regular 400 | 1.20 |
| Section label / caption | 12pt | regular 400 | 1.25 |
| Primary numeric value | 13pt | medium 500 | 1.25 |

Numeric typography contract:

- Network rates, temperatures, RPM, wattage, percentages, memory values, PID text, and process trailing values use monospaced digits.
- Numeric values are right-aligned in fixed-width frames.
- Long numeric strings must not scale below `0.9`; if a fixture needs smaller text, increase the fixed value width instead.
- Label text is lower priority than numeric text and truncates before the value column moves.

## Color

Use adaptive macOS semantic colors, not hard-coded light-only colors.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `NSColor.windowBackgroundColor` / default popover background | Popover base surface |
| Secondary (30%) | `Color.primary.opacity(0.04)` | Metric cards, battery section, temperature/fan section, process sections |
| Accent (10%) | `Color.accentColor`, `.blue`, `.orange`, thermal semantic colors | Reserved elements listed below |
| Destructive | `.red` | Destructive actions only; Phase 12 adds none |

Accent reserved for:

- Download/network receive values and progress: `.blue`.
- Upload/network send values and self-warning values: `.orange`.
- Metric progress bars and primary metric values where the existing metric severity color already applies.
- Thermal severity text only when representing system thermal state.
- Do not use accent color for section backgrounds, generic labels, empty states, captions, or layout-only fixture markers.

---

## Visual Hierarchy

Primary visual anchor is the metric grid at the top of the popover. Secondary anchors are stable numeric value columns in each section, especially network, battery/power, temperature, fan RPM, and process trailing metrics. Captions, labels, PID text, and empty/loading copy visually yield through secondary color, smaller type, truncation, or separate caption rows; they must not compete with the numeric columns.

## Copywriting Contract

Phase 12 is layout hardening. It must not add new feature copy, onboarding, alerts, or fan-control language.

| Element | Copy |
|---------|------|
| Primary CTA | No new primary CTA. Preserve compact popover behavior. |
| Empty state heading | Network process list: `暂无活跃网络进程`; CPU process list: `暂无 CPU 进程采样`; Memory process list: `暂无内存进程采样`. |
| Empty state body | Network process list: `等待新的网络进程活动`; CPU process list: `等待 CPU 采样更新`; Memory process list: `等待内存采样更新`. Do not use a generic empty-state label. |
| Error state | Inline only: `采样暂不可用，稍后重试` when a layout-owned fallback string is needed. Do not show modal errors. |
| Destructive confirmation | None. Phase 12 does not add destructive actions or confirmations. Existing `Quit MacStatus` behavior is out of scope. |

Loading copy:

- If Phase 12 touches loading labels in process sections, use `采样中...`.
- Debug fixtures and layout probes are developer-only and must not create user-facing copy.

## Phase 12 Layout Contract

### Fixed Popover Width

| Surface | Contract |
|---------|----------|
| Popover root | `DashboardView` uses one named fixed width constant: `372pt`. |
| Allowed range | `360-380pt`; `320pt` is not a hard requirement for Phase 12. |
| Refresh behavior | Width must not change across refresh ticks, short/large values, fan availability, network spikes, process name length, or mixed `N/A` states. |
| AppKit bridge | Keep `NSHostingController.sizingOptions = [.preferredContentSize]`; do not set a conflicting `NSPopover` width. |
| Identity | Preserve compact MacStatus menu bar popover style; no landing page, dashboard redesign, decorative background, chart expansion, or new navigation. |

Popover height may differ when whole sections are enabled/disabled by settings or hardware support. For the same visible section set, height must not change because numeric values become longer.

### Stable Value Widths

These are the minimum contract widths for Phase 12 hotspots. Planner/executor may increase a width only if deterministic fixtures prove clipping; reductions are not allowed without updating the contract.

| Value Kind | Width | Alignment | Required Fixtures |
|------------|-------|-----------|-------------------|
| Percentage metric | 64pt | trailing | `1%`, `100%`, `N/A` |
| Network card two-line value | 76pt | trailing | `↑1K\n↓2K`, `↑999T/s\n↓999T/s` or current formatter equivalent |
| Network process upload/download pair | 148pt total | trailing | two fixed `68pt` value cells plus `12pt` internal gap |
| Temperature | 56pt | trailing | `35°C`, `100°C`, `N/A` |
| Fan RPM | 78pt | trailing | `999 RPM`, `9999 RPM`, `N/A` |
| Battery/power value | 104pt | trailing | `—`, `充电 999.9W`, `耗电 999.9W`, `999.9W` |
| Battery health/time | 112pt | trailing | `—`, `计算中`, `99小时59分`, `100%（999 次循环）` |
| Process CPU trailing value | 52pt | trailing | `0.1%`, `999.9%`, `—` |
| Process memory trailing value | 68pt | trailing | `1K`, `999T`, `—` |

Implementation rules:

- Use fixed `width`, not `minWidth`, for Phase 12 value columns.
- Value frames carry higher layout priority than labels or process names.
- Do not pad strings with spaces to fake alignment.
- Do not change `ByteFormatting` semantics to solve layout; reserve enough width for its current bounded outputs.

### Text Yield Rules

| Text Source | Contract |
|-------------|----------|
| Process name | One line, tail truncation, left region takes remaining width after trailing value reservation. |
| PID | Stays with process name in the left region; PID must not compress trailing metrics. |
| Sensor/fan label | One line, tail truncation when paired with a value. |
| Fan range/target/status copy | Full-width caption below the RPM row; max 2 lines with stable line policy. |
| Header/status metadata | May truncate or stay short; must not widen cards or move value columns. |
| Numeric values | Never yield to text labels. Values remain visible and right-aligned. |

Long explanatory copy may move to a caption line, but it must not participate in the paired label/value row's width negotiation.

### Section Contracts

| Section | Required Stability |
|---------|--------------------|
| Metric grid | Two equal columns. Card height stable for short/extreme CPU, memory, GPU, and two-line network values. |
| Battery | Rows use stable value columns for time, power, system power, and health. Long values do not widen the section. |
| Temperature and fan | Header primary CPU/SoC value, temperature rows, fan RPM rows, and fan captions use the stable value/caption rules. |
| Network Top Processes | Upload and download values use fixed cells; long process names and PID text truncate before metrics move. |
| CPU/Memory Top Processes | Trailing CPU and memory values use fixed cells; long process names truncate. |
| Footer | Self CPU/RAM metadata and quit button stay compact; Phase 12 does not redesign footer interactions. |

## Interaction Contract

| Interaction / State | Contract |
|---------------------|----------|
| Open popover | Popover appears at the fixed root width and keeps current transient outside-click behavior. |
| Refresh tick | Text may update, but root width, metric card widths, value-column widths, and row alignment do not jump. |
| Loading | Existing process loading states remain inline and centered; loading text must not change the root width. |
| Empty data | Empty states remain inline in their section and do not create modal, toast, or alert surfaces. |
| Read failure / unsupported data | Use existing `N/A`, `—`, or inline error degradation. No modal errors. |
| Settings toggles | Existing settings determine section visibility; Phase 12 does not add new toggles. |
| Fan control | No manual fan control, opt-in, sliders, RPM inputs, helper/XPC prompts, or SMC write UI in Phase 12. |
| Status bar | No new temperature/fan/status-bar segments; status-bar formatting compatibility must be preserved if shared helpers are touched. |

## Deterministic Verification Contract

Phase 12 acceptance requires deterministic layout evidence, not a single live visual check.

Required fixture states:

| Fixture | Must Include |
|---------|--------------|
| Short fixture | Short network rates, short percentages, one fan with `999 RPM`, nominal `35°C`, short process names, available and unavailable mixed rows. |
| Extreme fixture | Large network rates, `9999 RPM`, `100°C`, `N/A`, large wattage, long process names, long sensor/fan labels, long capability/status captions, mixed battery/thermal/fan/process availability. |
| Same-visibility pair | Short and extreme fixtures with the same section visibility so width/height deltas prove text-length stability rather than section changes. |

Required checks:

- Measured short and extreme root widths equal `372pt` with tolerance no larger than `0.5pt`.
- For same-visibility fixtures, popover height does not change because numeric values lengthen.
- Value columns keep the same x-position and width between short and extreme fixtures for network, temperature, RPM, battery/power, and process trailing values.
- Fixture verification output is captured in the phase verification artifact.
- SwiftUI previews alone are not sufficient unless backed by a scriptable size probe or XCTest/view-size assertions.
