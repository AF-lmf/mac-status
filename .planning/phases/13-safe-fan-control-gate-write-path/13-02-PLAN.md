Build the privileged-helper infrastructure: FanControlProtocol (shared XPC interface), SMCWriter (root-side SMC write primitives), FanControlHelperImpl (Ftst unlock sequence implementation), the helper binary entry point, and the LaunchDaemon plist.

    The implementation runs synchronously on a background dispatch queue (the XPC framework calls this on an XPC queue, not @MainActor — Thread.sleep is acceptable here). Do NOT dispatch to any actor.

    The Ftst unlock sequence (per RESEARCH Pattern 3 and PATTERNS.md lines 264–298):
    1. Guard writer.isOpen (exposed as internal var or checked via try writeUI8 guard). If not open, reply(false, FanControlError.smcNotOpen.rawCode); return.
    2. Write Ftst=1 via writeUI8(key: "Ftst", value: 1). On throw: reply(false, FanControlError.writeFailed(key:"Ftst").rawCode); return.
    3. Poll F0Md: loop until mode != 3, max 10 seconds, 100ms intervals (Thread.sleep(forTimeInterval: 0.1)). Read via readUI8(key: "F0Md"). If timeout: write Ftst=0 (cleanup); reply(false, FanControlError.unlockTimeout.rawCode); return.
    4. Write F0Md=1 (writeUI8 key:"F0Md" value:1). On throw: write Ftst=0; reply(false, err); return.
    5. Write F1Md=1 (writeUI8 key:"F1Md" value:1). On throw: write F0Md=0; Ftst=0; reply(false, err); return.
    6. Write F0Tg=Double(rpm) (writeFloatRPM key:"F0Tg"). On throw: write F0Md=0, F1Md=0, Ftst=0; reply(false, err); return.
    7. Write F1Tg=Double(rpm) (writeFloatRPM key:"F1Tg"). On throw: write F0Tg back (probe-read existing value if possible, or 0), F0Md=0, F1Md=0, Ftst=0; reply(false, err); return.
    8. Write Ftst=0 (release lock). On throw: best-effort only; continue.
    9. reply(true, 0).

    On any catch at the outermost level: attempt F0Md=0, F1Md=0, Ftst=0 best-effort; reply(false, -1).

    Implement restoreAutoControl(reply: @escaping (Bool) -> Void):
    1. Try writeUI8(key: "F0Md", value: 0). Capture error.
    2. Try writeUI8(key: "F1Md", value: 0). Capture error.
    3. Try writeUI8(key: "Ftst", value: 0). Capture error (ensure unlock is always released).
    4. If any write threw, reply(false); return.
    5. reply(true).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Main app (user process) → XPC → FanControlHelper | XPC connection; helper runs as root; only two bounded methods exposed |
| FanControlHelper (root) → AppleSMC IOKit | Hardware write; F0Md/F1Md/F0Tg/F1Tg/Ftst only; no arbitrary key passthrough |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-02-01 | Elevation of Privilege | FanControlProtocol XPC interface | mitigate | Protocol exposes ONLY setManualTarget(rpm:) and restoreAutoControl(); no raw key passthrough; NSXPCInterface validates at runtime; RPM clamping enforced in main app before XPC call |
| T-13-02-02 | Tampering | RPM value from XPC caller (rpm: UInt16) | mitigate | UInt16 range (0–65535) is inherently bounded; values below F{i}Mn will be clamped by main app (FanControlManager) before the XPC call; helper does NOT enforce RPM bounds independently in this plan — defense-in-depth clamping added in Plan 03 FanControlManager |
| T-13-02-03 | Denial of Service | Ftst stuck at 1 after helper crash | mitigate | Ftst=0 is written in all error branches including outermost catch; deinit calls close() which does not write but the helper's process exit lets thermalmonitord resume naturally within its next polling cycle |
| T-13-02-04 | Tampering | IOKit-success-only false positive | mitigate | All writeUI8 and writeFloatRPM calls check BOTH kIOReturnSuccess AND output.result == 0; firmware rejections (SmcBadCommand 0x82) surface as throw, not silent success |
| T-13-02-05 | Tampering | Malicious XPC connection (non-MacStatus app calling helper) | mitigate | SMAppService.daemon registers the helper in System Settings; helper uses MachServices name for XPC; in production, code-signing and hardened runtime on both helper and main app ensure only the signed MacStatus app can connect; for development, developer cert + same team ID applies |
| T-13-02-SC | Tampering | npm/pip/cargo installs | accept | No package manager installs; pure Apple system frameworks |
</threat_model>
