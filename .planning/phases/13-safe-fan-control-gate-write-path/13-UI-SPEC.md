# Phase 13 — UI Design Contract

> Visual and interaction contract for the first SMC write-path UI in MacStatus. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope: opt-in master toggle (Settings), one-time risk dialog, manual-control affordance inside the existing `温度与风扇` popover section, verification-gated state copy, calm fail-closed presentation, and helper-approval states. All prose is English; all user-facing copy is Chinese to match the existing app.
>
> **Tech stack note:** MacStatus is a native macOS SwiftUI menu-bar app. There is no web/React design system. The shadcn initialization gate is **not applicable** (`Tool: none`); the design system is the existing MacStatus SwiftUI design language already established in `DashboardView.swift`, `SettingsView.swift`, and `StableValueLayout.swift`. This contract extends that language — it does not introduce a new one.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native SwiftUI; shadcn not applicable) |
| Preset | not applicable |
| Component library | SwiftUI system components (`Toggle`, `Slider`, `Button`, `Divider`) + existing in-house helpers (`StableValueRow`, `StableValueText`, `StableCaptionText`) |
| Icon library | SF Symbols (system) — used sparingly, matching existing `line.3.horizontal` / `exclamationmark.triangle.fill` usage |
| Font | System font (San Francisco). Numeric values use `.monospaced` design with `.monospacedDigit()` |

**Reused infrastructure (do NOT re-specify or rebuild):**
- `DashboardLayout.popoverWidth = 372` (Phase 12, LOCKED) — the control affordance lives inside the popover and MUST NOT change this width or cause horizontal/vertical jitter.
- `StableValueText` (right-aligned, monospaced, `.monospacedDigit()`, fixed `width`, `layoutPriority(1)`) — the ONLY way the target RPM value renders. New value width token added below.
- `StableValueRow` (label yields, value column fixed) — used for the mode/target rows.
- `StableCaptionText` (full-width `.caption2` secondary, 2-line) — used for all calm inline status / capability copy.
- Card surface: `RoundedRectangle(cornerRadius: 8).fill(Color.primary.opacity(0.04))` with `.padding(8)` — the control affordance attaches inside the existing `温度与风扇` card; it does NOT add a new card.

## Spacing Scale

Declared values (multiples of 4; matches the existing `DashboardView` 8-point rhythm):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Caption-to-caption gaps, slider-to-label gap, icon-to-text inline gap |
| sm | 8px | Default intra-section vertical spacing (`温度与风扇` section spacing; control rows) |
| md | 12px | Popover root padding (`.padding(12)`) and metric-card inner padding (`10` is the existing card pad — see exception) |
| lg | 16px | Risk-dialog content block spacing / dialog edge insets |
| xl | 24px | Risk-dialog outer padding (top/bottom around the full message) |

**Exceptions (pre-existing, preserved — do NOT "fix" to the 4-grid):**
- Existing cards use `.padding(10)` internally and the `温度与风扇` card uses `.padding(8)`. The new control affordance lives **inside** the `温度与风扇` card and inherits its `8px` rhythm; it MUST NOT introduce a different inner padding.
- The risk-confirmation dialog is a system `confirmationDialog`/`Alert`-style sheet; its outer chrome spacing is owned by AppKit/SwiftUI and is out of token scope. Only the body copy block spacing (`16px`) is specified.

## Typography

Matches the existing popover scale exactly. The popover is dense; only three roles are used (plus the monospaced value variant). Two weights only: `regular` and `medium`/`semibold`.

| Role | SwiftUI font | Size | Weight | Usage |
|------|--------------|------|--------|-------|
| Section label | `.caption` | 12pt | regular (`.secondary`) | `温度与风扇` header, row labels (`手动控制`, `当前模式`, `目标转速`) |
| Caption / status | `.caption2` | 11pt | regular (`.secondary` / semantic color) | All calm inline status copy, capability notes, range/target captions, helper-approval guidance |
| Value (numeric) | `.system(.body, design: .monospaced)` | 13pt | medium | Target RPM value in the fixed value column (mirrors temperature/fan value styling) |
| Dialog body | `.body` | 13pt | regular | Risk-confirmation dialog explanatory paragraphs |
| Dialog title | `.headline` | 13pt | semibold | Risk-confirmation dialog title |

Line height: SwiftUI system default per text style (do not override). Body/dialog copy wraps; numeric value never wraps (`lineLimit: 1`).

**Weight rule:** exactly two weights in use — `regular` for labels/body/captions, `medium`/`semibold` for the numeric value and the dialog title. No other weights.

## Color

The app is theme-adaptive (light/dark) and uses **semantic system colors**, not hardcoded hex, everywhere except the two pre-existing threshold defaults. The 60/30/10 split maps onto macOS materials.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | System window/popover background material (default) | Popover and dialog background; never explicitly painted |
| Secondary (30%) | `Color.primary.opacity(0.04)` card fill | The `温度与风扇` card the control lives in; no new card color |
| Accent (10%) | `Color.accentColor` (system accent) | **Reserved for:** the primary `恢复系统自动控制` button label/affordance, and the "Open System Settings" action button in the helper-approval state. Nothing else. |
| Destructive / caution | System orange (`.orange`) for caution; system red (`.red`) for serious/critical | The **risk-confirmation dialog's** confirm button is `.destructive` role (system red). The inline `控制未生效，已恢复自动` calm message uses `.secondary` (NOT red — see calm-degradation rule). `.orange` is reserved for an at-a-glance caution glyph if used in the dialog only. |

**Accent reserved-for (explicit list — never "all interactive elements"):**
1. `恢复系统自动控制` button (the always-visible restore affordance while manual mode is engaged).
2. `打开系统设置` button in the helper not-yet-approved state.

The opt-in `Toggle` uses the **system switch tint** (default), consistent with every other toggle in `SettingsView`. The slider uses the **default system tint**. Neither claims the accent budget.

**Calm-degradation color rule (LOCKED, D-10/D-12, matches Phase 10/11):**
- Unavailable / capability-off / "restored to auto" copy is **`.secondary`**, never red, never an error color. Red/orange are reserved for genuine thermal severity (`系统状态` row) and the destructive confirm button — never for the fail-closed control message. A write failure that auto-restores is a **calm** state, not an error state.

## Copywriting Contract

All user-facing strings are Chinese. The planner may refine wording but MUST preserve meaning and the locked safety invariants (default-auto, explicit opt-in, clamp, read-back-before-success, always-available verified restore, fail-closed).

### Settings — Opt-in master toggle (D-01, D-04)

| Element | Copy |
|---------|------|
| Toggle label | `风扇手动控制` |
| Toggle placement | New row inside the existing `弹窗区块` Section of `SettingsView`, below `风扇区块` (manual control is a sub-capability of the fan section). Default **OFF**. |
| Toggle help caption (optional, `.caption2 .secondary`) | `仅在受支持的 MacBook Pro 上可用，写入前会读回验证` |
| **Visibility gate (D-04, LOCKED)** | When `FanCapabilities.safeControlAvailable == false`, the toggle row is **not rendered at all** (hidden, not shown-disabled). No placeholder, no disabled switch. Read-only monitoring is unchanged. |

### Risk-confirmation dialog (one-time, first enable — D-02)

Shown the first time the user turns the toggle ON (gated by a separate `hasConfirmedFanRisk` flag, default false). Not re-shown afterward (D-03).

| Element | Copy |
|---------|------|
| Title | `开启手动风扇控制？` |
| Body paragraph 1 (risk) | `手动控制会直接调整风扇转速。设置过低可能导致设备过热。` |
| Body paragraph 2 (clamp promise) | `MacStatus 会把目标转速限制在硬件安全范围内，不能低于系统默认下限，也不能让风扇停转。` |
| Body paragraph 3 (restore promise) | `写入失败或退出应用时，MacStatus 会自动恢复系统自动控制。` |
| Confirm button (`.destructive` role) | `开启手动控制` |
| Cancel button (`.cancel` role) | `取消` |
| On cancel | Toggle reverts to OFF; system remains in auto control; no state change. |

### Manual control affordance — inside `温度与风扇` section (D-03, D-05, D-08, D-11)

Rendered only when the toggle is ON **and** `safeControlAvailable == true` **and** the helper is `.enabled`.

| Element | Copy |
|---------|------|
| Sub-header label | `手动控制` (`.caption .secondary`, same style as `温度与风扇` header) |
| Current mode row label | `当前模式` |
| Mode value — auto | `系统自动` |
| Mode value — applying/pending (D-08) | `正在应用…` |
| Mode value — manual verified (D-08, LOCKED) | `手动已生效` |
| Target row label | `目标转速` |
| Target value | `{rpm} RPM` rendered via `StableValueText` (monospaced, right-aligned, fixed width `StableValueWidth.fanTargetRPM`) |
| Slider accessibility label | `风扇目标转速，范围 {min} 到 {max} RPM` |
| **Primary CTA (restore)** | `恢复系统自动控制` (accent button, **always visible while manual mode is engaged**, D-11) |
| Slider bounds caption (`.caption2 .secondary`) | `可调范围 {min}-{max} RPM` |

**Slider contract (D-05, D-06, D-07, LOCKED):**
- A single `Slider` bounded to the live hardware `[min, max]` (unified target across all fans; clamped per-fan on apply). The slider **cannot** physically request below `min` (Apple floor) or a stall/silent value — `min`/`max` are the live hardware bounds, never 0.
- No free-form numeric text entry. The slider is the source of truth. The resulting RPM is a **read-only** label in the fixed value column.
- Slider value commits on drag-end (not continuously), to avoid a write storm into the privileged helper.

### State copy — verification-gated and calm fail-closed (D-08, D-10, D-12)

| State | Trigger | Copy | Color |
|-------|---------|------|-------|
| Auto (baseline) | Manual mode not engaged | mode = `系统自动` | `.secondary` |
| Pending / applying | Write sent, read-back not yet confirmed | mode = `正在应用…` + slider temporarily non-interactive | `.secondary` |
| Manual verified | Read-back confirms mode+target (D-08) | mode = `手动已生效` | `.primary` |
| Fail-closed (write failed or read-back disagrees) | D-10 | inline `控制未生效，已恢复自动` (auto-restore already attempted; UI reverts to auto) | `.secondary` (calm, NOT red) |
| Restore unverifiable | Restore itself cannot be read-back confirmed (D-11) | inline `正在恢复自动控制…` then, if still unconfirmed, `恢复未确认，请稍候` (hold restore-to-auto posture) | `.secondary` |
| Capability unavailable | `safeControlAvailable == false` (D-12) | inline `控制未启用` (consistent with Phase 11's `边界可读，控制未启用`) | `.secondary` |

**LOCKED rules:**
- `手动已生效` appears **only after** read-back confirms mode + target (D-08). An IOKit "success" return alone never flips this label.
- Fail-closed presentation is **inline only** — NO modal, NO repeated error toasts/spam (D-10). One calm caption that auto-clears.

### Helper-approval states (SMAppService daemon — from RESEARCH, Pitfall 4)

The privileged helper requires one-time approval in System Settings. These states are calm and inline, consistent with calm-degradation. Poll-based per research (`SMAppService.daemon.status` every ~2s).

| State | Copy | Affordance |
|-------|------|------------|
| Not yet registered / registering | `正在准备风扇控制助手…` (`.caption2 .secondary`) | none (transient) |
| Awaiting approval (`.requiresApproval`) | `请在 系统设置 › 登录项 中允许 “MacStatus 风扇控制助手”` (`.caption2 .secondary`) | `打开系统设置` button (accent) opening `x-apple.systempreferences:com.apple.LoginItems-Settings.Extension` |
| Approved (`.enabled`) | (no banner; control affordance becomes available) | — |
| Registration failed / cannot verify | `控制未启用`（fail-closed, D-12; toggle hidden / control absent） | none |

### Destructive actions

| Action | Confirmation approach |
|--------|----------------------|
| Enabling manual fan control (first time) | One-time `confirmationDialog` with `.destructive` confirm role (D-02). Subsequent enables do NOT re-confirm (D-03). |
| Setting a manual RPM target | No per-write confirmation (the slider is bounded and clamped; risk was accepted at opt-in). Write is read-back verified; failure auto-restores calmly. |
| Restoring system auto control | No confirmation — restore is always-safe and is the recovery action itself; it is one click (D-11). |

## New Layout Tokens (additions to `StableValueWidth`)

| Token | Value | Rationale |
|-------|-------|-----------|
| `StableValueWidth.fanTargetRPM` | `78` (reuse `fanRPM` width) | Target RPM value (`9999 RPM` worst case) must share the same fixed, right-aligned, monospaced column width already proven for fan RPM in Phase 12. Reuse the existing `fanRPM = 78` width rather than introducing a divergent column, so the manual-control target value aligns vertically with the read-only fan RPM rows in the same card. |

**Width-stability requirement (Phase 12 carry-forward, LOCKED):** Across all control states (`系统自动` / `正在应用…` / `手动已生效` / `控制未生效，已恢复自动` / `控制未启用`), the popover MUST remain at 372pt with no horizontal or vertical jitter. Status copy uses full-width `StableCaptionText` (which yields, never pushes the value column). The mode value text varies in length (`系统自动` vs `正在应用…` vs `手动已生效`) and therefore lives on the **label side** of `StableValueRow`, not the fixed value column, so it cannot disturb the numeric column.

## Interaction State Machine (executor reference)

```
                ┌────────────── safeControlAvailable == false ──────────────┐
                │                                                            ▼
   [READ-ONLY / toggle hidden]                                      "控制未启用"
                │ (capability gate passes; helper enabled; toggle ON)
                ▼
        [AUTO baseline]  mode="系统自动"
                │ user drags slider (commit on drag-end)
                ▼
        [PENDING]  mode="正在应用…"  (write via XPC helper; slider locked)
                │
        ┌───────┴─────────────────────────┐
        │ read-back confirms mode+target   │ read-back fails / disagrees
        ▼                                  ▼
 [MANUAL VERIFIED]                  [FAIL-CLOSED]
 mode="手动已生效"                  auto-restore attempted → "控制未生效，已恢复自动"
        │ user clicks 恢复系统自动控制               │
        ▼                                          ▼
 [RESTORING]  "正在恢复自动控制…"            [AUTO baseline]
        │ read-back confirms auto
        ▼
 [AUTO baseline]
```

Helper-approval flow runs **before** AUTO baseline becomes reachable: registering → `.requiresApproval` (show `打开系统设置`) → poll → `.enabled` → capability gate flips → control affordance appears. If approval never completes, stays fail-closed (`控制未启用`).
