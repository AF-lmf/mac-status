## Spacing Scale

Declared values for new Phase 11 UI use SwiftUI points and must stay within the existing compact popover rhythm.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Optional fan detail line spacing; label-to-subtext grouping |
| sm | 8pt | Row spacing, section stack spacing, fan row inner spacing |
| md | 16pt | Horizontal separation and stable trailing value reserve when needed |
| lg | 24pt | Reserved; do not add new Phase 11 section gaps unless existing layout requires it |
| xl | 32pt | Not used in Phase 11 |
| 2xl | 48pt | Not used in Phase 11 |
| 3xl | 64pt | Not used in Phase 11 |

Exceptions:
- Preserve existing `DashboardView` outer `.padding(12)` and `.frame(width: 320)`.
- Phase 11 must not add or reuse `10pt` spacing. New or changed fan/combined-section spacing uses the declared 4pt-multiple tokens, with `8pt` as the standard inner card and row spacing.
- Existing unrelated `10pt` padding in sibling code may remain untouched only if Phase 11 does not edit that specific layout.
- Settings list rows preserve the existing `44pt` row-height convention for toggle rows.

Popover frame contract:
- Phase 11 must keep the popover width at `320pt`.
- Do not expand to `360-380pt`; that belongs to Phase 12 layout hardening.
- The combined section uses the existing full-width card treatment: `RoundedRectangle(cornerRadius: 8)` with `Color.primary.opacity(0.04)`.
- Placement remains after battery when battery is visible and before process sections.

## Typography

Phase 11 declares exactly three text sizes and two weights for new UI.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body/value | 13pt (`.body`) | medium (500) | 1.3 |
| Row label/value | 12pt (`.caption`) | regular (400) | 1.3 |
| Micro/detail | 11pt (`.caption2`) | regular (400) | 1.3 |

Usage:
- Combined section title `温度与风扇`: `.font(.caption)`, `.foregroundStyle(.secondary)`.
- Primary summary value: `.font(.system(.body, design: .monospaced))`, `.fontWeight(.medium)`.
- Temperature and fan rows: labels use `.caption` secondary; trailing values use `.system(.caption, design: .monospaced)` secondary or primary when used as the row's main value.
- RPM numbers must be rounded to whole RPM, right-aligned, and monospaced.
- Optional bounds/detail copy uses `.caption2` secondary and must not dominate the primary RPM row.
- Do not introduce display type, custom fonts, animated counters, or warning-style bold labels in Phase 11.

## Color

Use system dynamic colors so the popover remains correct in Light/Dark Mode and accessibility appearances.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `NSColor.windowBackgroundColor` / SwiftUI default popover background | Popover base surface |
| Secondary (30%) | `Color.primary.opacity(0.04)` | Combined `温度与风扇` card background, matching existing cards |
| Accent (10%) | `Color.accentColor` | Settings toggle focus/interactive affordance only |
| Warning | existing system orange (`#FF9500` equivalent) | Existing thermal state `.serious` only; fan read failures do not become warning UI |
| Destructive | existing system red (`#FF3B30` equivalent) | Existing thermal state `.critical`; destructive actions only, none introduced in Phase 11 |

Accent reserved for: native Settings controls, keyboard focus rings, and existing settings actions already using accent color. Accent is not used for normal fan readings, capability labels, RPM values, or future-control promises.

Fan semantic color contract:
- Readable RPM: primary or secondary foreground, matching existing row hierarchy.
- `N/A` / unreadable optional data: secondary foreground.
- `边界可读，控制未启用`: secondary foreground only.
- No red/orange fan state solely because a fan field is unreadable; unavailable telemetry is a quiet state.

## Phase 11 Popover Contract

### Section Structure

Replace the existing `散热` section title with `温度与风扇`. The section remains one full-width card and contains two independently gated groups:

1. Temperature group, gated by `SettingsManager.showThermalSection`.
2. Fan group, gated by the new `SettingsManager.showFanSection`.

Required behavior:
- If only temperature is enabled, the section title still reads `温度与风扇` only if the implementation uses one combined container; otherwise the visible content may preserve the existing thermal rows without fan rows. Do not create a separate top-level `风扇` card.
- If only fan is enabled and fan data is supported/readable, render the same combined card with fan rows.
- If both toggles are disabled, hide the whole combined section.
- If both toggles are enabled, render temperature rows first, then fan rows.

### Fan Row Content

Render one primary row per detected fan. The primary value is current RPM.

Required row shape:
- Left label: stable display name, defaulting to `风扇 1`, `风扇 2`.
- Right value: whole-number RPM such as `1454 RPM`, or `N/A`.
- Optional detail below the row or as compact secondary text: min/max range and target only when readable.

Local Mac15,9 contract:
- The local probe found 2 readable fans with min/max/target readable.
- `F0ID` / `F1ID` were unavailable, so default labels must be numbered unless implementation adds reliable left/right evidence.
- Do not infer `左风扇` / `右风扇` from fan index alone.

Optional detail rendering:
- Show `范围 1350-5349 RPM` only when both min and max are readable and plausible.
- Show `目标 1446 RPM` only when target is readable.
- Omit missing optional details; do not reserve blank subrows for unreadable min/max/target.
- If bounds are readable but a user might infer control, add secondary copy `边界可读，控制未启用`.

### Unsupported and Unavailable States

Unavailable is normal and quiet.

| Condition | UI Result |
|-----------|-----------|
| Fanless machine, non-MacBook-Pro, `FNum` absent, or fan count zero | No fan rows by default; no unsupported hardware message in normal popover use |
| Expected fan surface on MacBook Pro but current RPM unreadable | Keep a stable fan row and show `N/A` or `风扇不可读取` |
| Current RPM readable, bounds unreadable | Show RPM row; omit range/target detail |
| Bounds readable, current RPM unreadable | Show `N/A` as primary value and optional bounds only if capability is stable |
| Single tick read failure | Do not show modal, alert, toast, red card, or repeated error copy |
| All fan values unavailable on expected fan hardware | Stable inline unavailable row only; no controls and no warning surface |

Rows should not appear/disappear due solely to one transient read tick. Capability/support changes may update after setup, wake, or a deliberate re-probe.

## Settings Contract

Add one toggle in `SettingsView` under the existing `弹窗区块` section.

| Setting | Contract |
|---------|----------|
| User-visible label | `风扇区块` |
| Storage key | `showFanSection` or equivalently named key matching existing `showThermalSection` pattern |
| Default | `true` |
| Persistence | `UserDefaults`, matching `showBatterySection`, `showProcessSection`, and `showThermalSection` |
| Notification | Setter posts `.settingsDidChange` with the changed key |
| Runtime behavior | Applies live through SwiftUI observation and existing settings refresh behavior; no relaunch |

Toggle placement:
- Place `风扇区块` directly after `散热区块` in `弹窗区块`.
- Do not add control toggles, fan mode toggles, manual RPM settings, disabled future controls, or Settings placeholders for Phase 13.
- `散热区块` and `风扇区块` must be independently controllable.

## Accessibility Contract

- Preserve native SwiftUI controls and system text colors for VoiceOver, Dark Mode, and increased contrast.
- Section accessibility label: `温度与风扇信息`.
- Fan row accessibility labels:
  - Readable RPM: `风扇 1 当前转速 1454 RPM`.
  - Unreadable RPM: `风扇 1 转速不可用`.
  - Bounds detail: `风扇 1 范围 1350 到 5349 RPM`.
  - Target detail: `风扇 1 目标转速 1446 RPM`.
- Settings toggle must expose the native label `风扇区块`.
- Do not rely on color alone to indicate readable/unreadable state; `N/A` or explicit unavailable copy is mandatory.

---

## Interaction Contract

- Phase 11 fan UI is read-only.
- There are no buttons, sliders, steppers, menus, disclosure controls, row click actions, drag handles, or editable fields inside fan rows.
- Refresh follows the existing collector interval. The UI must not add a separate fan loading spinner.
- Opening/closing the popover does not trigger visible fan-control state changes.
- Settings changes apply live and must not write SMC keys.
- The capability model may exist internally, but UI must not expose a promise that control is available.

---

## Layout Mechanics

- Keep `DashboardView` at `320pt` width.
- Use `HStack { Text(label); Spacer(); Text(value) }` for primary fan rows, matching thermal/battery row patterns.
- Right values are right-aligned and monospaced.
- Reserve enough trailing value width for `9999 RPM` and `N/A`; prefer `minWidth: 72pt` for fan RPM values if a local row helper needs explicit width.
- Long labels or optional detail copy must not push the RPM value out of alignment.
- No charts, sparklines, gauges, progress bars, fan icons, badges, nested cards, raw key tables, scrollable fan subareas, or popover-inside-popover in Phase 11.
- Full deterministic stress testing for extreme RPM/temperature/network strings remains Phase 12; Phase 11 should still avoid obvious row wrapping inside the 320pt boundary.

---

## Must Not Change in Phase 11

- Do not add manual fan control, disabled controls, future-control affordances, sliders, buttons, steppers, mode toggles, or `恢复自动`.
- Do not add SMC write paths, helper/XPC components, privileged prompts, fan force-mode state, or lifecycle restore-auto behavior.
- Do not add a status-bar fan segment, temperature segment, menu-bar fan icon, or `metricOrder` / `enabledMetrics` fan item.
- Do not persist fan samples to SQLite, history, charts, or `MetricSample`.
- Do not add notifications, warning alerts, fan threshold settings, fan curves, quiet mode, or remote control.
- Do not add a raw SMC browser or user-facing key enumeration UI.
- Do not expand the popover width beyond 320pt in this phase.
- Do not label fans left/right unless reliable position evidence is recorded.
