  </read_first>
  <action>
    在现有 MetricCollector.swift 中进行最小化扩展，不改变任何现有逻辑。

    新增私有属性（在 tickCount 声明后）：
    - private var lastSample: MetricSample?
    - private var settingsObserver: NSObjectProtocol?

    修改 tick() 方法：在 "let sample = MetricSample(...)" 构造完毕后、ringBuffer.append(sample)
    调用前，插入一行：lastSample = sample
    （顺序：构造 sample → lastSample = sample → ringBuffer.append → pendingSamples.append → updateUI）

    新增 reconfigure() 方法（在 stop() 之后，作为独立 MARK 区块 "// MARK: - Live Re-apply"）：
    - 调用 timer?.invalidate()，然后 timer = nil
    - 读取 let interval = SettingsManager.shared.refreshInterval
    - 构造新 Timer：Timer.scheduledTimer(withTimeInterval: interval, repeats: true) { [weak self] _ in Task { @MainActor [weak self] in self?.tick() } }
    - 赋值 timer = 新 Timer
    - 注意：不调用任何 reader 方法（不调 setup()、stop()、readValue()）

    新增 applyNow() 方法（在 reconfigure() 后）：
    - guard let sample = lastSample else { return }
    - updateUI(sample: sample)

    修改 start() 方法：在现有 timer = Timer.scheduledTimer(...) 赋值完成后，追加调用
    setupSettingsObserver()（不修改 timer 创建代码本身）

    新增 setupSettingsObserver() 私有方法：
    - 使用闭包形式 addObserver(forName: .settingsDidChange, object: nil, queue: .main)
    - 回调中：guard let self，解包 userInfo?[SettingsManager.changedKeysUserInfoKey] as? Set<String>
    - 若 changedKeys.contains("refreshInterval") → self.reconfigure()
    - 否则 → self.applyNow()
    - 将返回的 token 存入 self.settingsObserver

    注意事项（per RESEARCH Pitfall 2）：
    - 绝对不在 reconfigure() 中调用 stop() 或 start()
    - 绝对不在 reconfigure() 中调用 reader.setup() 或 reader.stop()
    - stop() 方法保持不变（含 pendingSamples flush 逻辑）

    注意事项（per RESEARCH Pattern 3）：
    - 不使用 @objc #selector 形式（swift#74037 crash）
    - 始终用 addObserver(forName:object:queue:using:) 闭包形式
    - MetricCollector 是单例，理论上不会被 deinit，但仍保留 settingsObserver 属性以防 token 被 ARC 释放
  </action>
