# Plan 02-03: Gap Closure — Show Memory in the Visible Combined Status Item

## Objective

Fix the Phase 2 UAT failure where memory usage is not visible in the menu bar. The CPU visibility issue was resolved by rendering CPU inside the already-visible network status item; memory should use the same visible combined item instead of relying on a separate `memoryStatusItem`.

## UAT Gaps Addressed

- Test 1: menu bar metrics visible — user reported `mem没有显示`
- Test 3: memory usage display — user reported `没显示`

## Root Cause

`MemoryReader` is wired and calls `StatusBarManager.updateMemory(_:)`, but `StatusBarManager` still renders memory text into a separate `memoryStatusItem`. On the user's menu bar, separate CPU and memory status items are not visible, while the network status item is visible. The current combined status only includes CPU and network.

## Tasks

### Task 1: Fold Memory Text into the Visible Combined Status Item

**Files:**

- `MacStatus/MacStatus/UI/StatusBarManager.swift`

**Action:**

- Add `latestMemoryText = "MEM --/--"` state beside `latestCPUText` and `latestNetworkText`.
- Change `updateMemory(_:)` to update `latestMemoryText` and call `updateCombinedStatus()`.
- Change `updateCombinedStatus()` to render CPU, network, and memory together on `networkStatusItem`, for example: `CPU 12% ↓1K ↑1K MEM 8.2G/16G`.
- Increase `networkStatusItem` width enough for the combined string while keeping single-line clipping.
- Stop depending on `memoryStatusItem` for the user-visible display. It can be removed or left unused, but the visible truth must come from `networkStatusItem`.

**Verify:**

- Run `xcodebuild -project MacStatus/MacStatus.xcodeproj -scheme MacStatus -configuration Debug -derivedDataPath build build`.
- Restart the Debug app.
- Confirm the visible menu bar item includes `MEM`.

**Done:**

- The menu bar shows CPU, network, and memory in the visible combined item.
- Text remains single-line and compact.
- Phase 2 UAT tests 1 and 3 can be re-run and pass.
